Satu permintaan, sembilan langkah yang terlihat.

Tahapan ini menjelaskan pemeriksaan server sebelum ZIP dikirim langsung ke browser.

  1. Permintaan diterimaServer WHYZZZ menerima URL dari browser atau integrasi API.
  2. Validasi URLProtokol http/https, panjang, dan karakter yang tidak diizinkan.
  3. Pemeriksaan keamanan targetDNS harus mengarah ke alamat publik; localhost dan IP privat ditolak.
  4. Pemeriksaan redirectSetiap pengalihan diperiksa ulang, maksimal 5 hop.
  5. Menghubungi layanan pengarsipanPermintaan dikirim melalui POST JSON ke layanan FreeAPI.
  6. Menunggu responsLayanan dapat membutuhkan 10–75 detik; backend menunggu hingga 85 detik.
  7. Memvalidasi hasilHeader respons diperiksa untuk memastikan file ZIP valid.
  8. Menyiapkan unduhanTombol unduh muncul setelah file ZIP diterima.
  9. Berhasil atau gagalHasil akhir beserta alasannya tampil apa adanya.

Pertanyaan yang sering muncul

Format URL seperti apa yang diterima?+

Alamat lengkap dengan protokol, misalnya https://contoh.com. URL harus mengarah ke domain publik dan tidak memuat username atau password.

Apakah seluruh isi website akan tersimpan?+

Tidak selalu. Hasil bergantung pada akses publik, proteksi, konten dinamis, dan kemampuan layanan pengarsipan. Jumlah file yang dilaporkan tampil apa adanya; bila tidak dilaporkan, ditulis demikian.

Di mana file ZIP bisa diunduh?+

Jika proses berhasil, tombol unduh muncul di bawah Live Output. Simpan file segera setelah selesai.

Mengapa permintaan bisa gagal?+

Domain tidak ditemukan (DNS), target tidak dapat diakses atau menolak pengambilan, tautan unduhan tidak valid, atau layanan pengarsipan sedang gangguan. Live Output menampilkan penyebab yang dilaporkan.

Apakah ada batas jumlah permintaan?+

WHYZZZ tidak memasang cooldown atau kuota sendiri. Satu permintaan diproses satu per satu dari halaman ini, dan layanan pengarsipan maupun hosting dapat menerapkan batasnya sendiri.
